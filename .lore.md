### Architecture

<!-- lore:019f5699-447f-79a1-aa67-23c74f50b6ed -->
* **@freestyle-voice/stt postProcess: never-throw contract, onError hook, filler short-circuit**: \`postProcess\` in \`@freestyle-voice/stt\` never throws — on model call failure it falls back to sanitized raw text so callers always get usable output. Use the \`onError\` callback to observe failures (Sentry, telemetry, plugin events) since the caller has no other way to detect the fallback path was taken. Filler-only short-circuit: \`FILLER\_ONLY\_PATTERN = /\b(um+|uh+|ah+|er+|hm+|hmm+|mm+|mhm+|you know|i mean)\b/gi\` — trivial input never reaches the model. Default user prompt wraps text in \`\<transcript>\` tags with prompt-injection safeguard; caller can override entirely via \`prompt\` param. Returns \`model: null\` when cleanup is skipped (empty/filler input) or model call fails.

* **@freestyle-voice/stt vs @freestyle/stt: new shared package API differences**: \`@freestyle-voice/stt\` (PR #446, \`freestyle-voice/freestyle\`) is a provider-agnostic shared package — caller owns the model and API key, package never constructs a provider client or holds credentials. Public API: \`transcribe(params: {model: TranscriptionModel, audio, providerOptions?, signal?})\`, \`postProcess(params: {model: LanguageModel, text, system, prompt?, maxOutputTokens?, temperature?, providerOptions?, signal?, skipEmptyText?, onError?})\`, plus text utilities. Zero internal package deps; \`ai\` and \`@ai-sdk/provider-utils\` are peer deps. Will be published to npm (not vendored). \`text.ts\` and \`tokens.ts\` in \`cloud/packages/stt\` are byte-identical to npm equivalents — will be dropped and sourced from npm. \`asr-bias.ts\` differs: cloud uses greedy \`break\`; npm uses \`continue\` + 200-char reserve + word-boundary truncation (better term packing).

* **Desktop real-time STT: three-layer pipeline and WebSocket protocol**: Three layers: Electron Renderer (AudioWorklet \`pcm-processor.ts\` → \`streamer.ts\`) → Local Node Hono server (\`ws://127.0.0.1:4649/stream\`, \`stream.ts\` 610 lines) → Upstream STT provider. PCM: 16kHz mono, ~80ms chunks, 2560 bytes, Int16Array. Client→Server: binary ArrayBuffer frames + JSON control messages (\`start\`, \`context\`, \`commit\`, \`cancel\`). Server→Client: \`config\` (on open), \`session.ready\`, \`partial\`, \`final\` (LLM-cleaned only — raw STT never sent to client), \`error\` (code: \`cloud\_auth\_required\`). \`providerCategory\`: \`local\`|\`byok\`|\`freestyle\_cloud\`. State machine: ANNOUNCE CONFIG → CONNECT UPSTREAM (keepAlive) or WAIT FOR start (Soniox) → STREAMING → commit → FINALIZING → POST-PROCESS → DELIVER FINAL.

* **Durable Objects as streaming STT proxy: lifecycle and limits for real-time transcription**: DOs are viable for streaming STT proxy (Client WS → DO → outbound WS to Soniox/Deepgram + HTTP to Groq on commit). Key facts: wall time unlimited while client WS connected; 6 simultaneous outgoing connections/request; outbound WS keeps DO in idle non-hibernateable state (incurs duration charges, max 15min preventing eviction). Hibernation NOT possible while outbound WS is open. Each incoming WS message resets CPU budget to 30s. Deploying new Worker version disconnects ALL WebSockets. Use Hibernation API for inbound client WS (ctx.acceptWebSocket); serializeAttachment max 16,384 bytes for per-connection state across hibernation cycles.
